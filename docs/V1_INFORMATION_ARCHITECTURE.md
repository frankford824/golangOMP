# V8 信息架构

> 状态：V8 当前完整替换版。菜单、按钮和数据入口只由有效能力与后端 `allowed_actions` 派生。

## 1. 一级信息架构

```text
任务中心
├── 全部任务
├── 我的任务
├── 待审核
├── 已结单
└── 策划 SKU

资产中心
├── 任务资源组
└── 客户发布

权限管理
├── 能力目录
├── 角色矩阵
├── 人员授权
├── 组织策略
├── 有效权限预览
└── 权限审计

组织架构
├── 部门
├── 团队
└── 人员
```

组织架构用于人员主数据和显示。是否能看到菜单、任务和按钮由显式权限决定，名称变更不得
改变授权结果。

## 2. 任务中心

任务详情统一展示四步：`创建 -> 设计 -> 审核 -> 已结单`。修图与策划 SKU 只高亮其实际
经历的节点。页面操作栏完全消费 `allowed_actions`；`workflow_contract_version=2` 下空数组
表示明确禁止。

任务资源展示固定为：

```text
任务
└── SKU 或修图需求
    ├── 参考图
    ├── 当前有效源文件
    └── 当前最终成品图（单图或有序套装）
```

四个展示面必须消费同一 resource-bundle/resource-group read model：任务详情、任务资产、
资产中心和全局搜索。不得展示文件生命周期、产生模块、清理状态或历史版本等技术维度。

## 3. 设计与审核交互

设计提交抽屉按 SKU/范围显示：

- 默认单图，可切换套装。
- 套装支持拖拽和键盘排序。
- 可将模式应用到全部 SKU，同时仍允许逐项调整。
- 源文件与最终成品使用明确分区。
- 上传草稿支持单文件重试、离页保护和恢复。
- 200 SKU 使用虚拟滚动。

统一审核动作栏提供：打回设计、直接通过并结单、上传修改后通过。409 时刷新 workflow/group
revision 并保留本地未提交草稿，禁止静默覆盖。

## 4. 策划 SKU

创建入口有三种视图，但共用同一个 `planning_sku_items[]` 合同：

- 单条表单。
- 表格批量，最多 200 行。
- Excel 导入，先解析并展示逐行错误；存在任何错误时不可创建。

每行字段：产品图片、描述规格、数量、目标价、备注、参考链接，以及可选 ERP 字段。
产品图片最多一张且只属于策划修订，不进入资产中心或客户发布。

创建成功进入结果页：显示任务号、全部 SKU、逐行 ERP 状态、复制与批量导出。导出支持单任务、
多任务和勾选 SKU，最多 5000 行，文本单元格必须防公式注入。

## 5. 权限管理

权限中心面向具备 `access_policy.view/manage` 的管理员：

- 能力目录只读，URL 到能力映射由代码维护。
- 角色矩阵可维护业务角色和能力；系统保护角色不可删除。
- 人员授权一次提交完整角色和范围，禁止分两次保存。
- 范围选择使用稳定部门/团队 ID。
- 组织策略默认关闭，管理员显式启用后按稳定 ID 动态生效。
- 有效权限页展示角色、能力、范围、来源和策略 revision。
- 所有写操作要求原因并展示 409 冲突处理。

## 6. 全局搜索

搜索分两个业务域：

- 任务：任务号、SKU、策划描述规格、备注和 ERP 状态。
- 资产：资源组粒度，只返回当前 finalized revision 的参考、有效源和最终成品摘要。

内部用户结果受显式数据范围约束。客户和素材提交者只能命中已经发布并固定 revision 的最终成品。

## 7. Asset Workbench

asset-workbench 独立实现 resource-group 类型和卡片，不导入 main-ops shell、路由或样式。
客户发布固定 `finalized_revision_id`；套装必须指定封面但下载返回该固定修订全部最终成品，
且必须全有或全无。资源组后续产生新 finalized revision 时既有发布保持不变，只有显式重新发布
才切换。

## 8. 响应式与可访问性

- 桌面基线包含 1366x768；同时覆盖主流桌面和移动端。
- 排序、上传、审核和冲突提示必须可通过键盘完成。
- 大列表使用虚拟滚动，但不能破坏焦点顺序和屏幕阅读器标签。
- 所有状态不能只依赖颜色表达。
