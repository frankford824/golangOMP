# 正式 OA 订单接线

订单接口只读取 jst 开放视图。默认 ClickHouse 地址为 tailnet 私网地址，密码来自 OPS_READER_PASSWORD。订单经营、SKU 成交、退款、台账和刷单口径沿用开放合同。任务和成本读取通过同进程指定的正式原生 GET 入口，以当前调用者验权。

- 创建或办理任务使用原生 /v1/tasks。创建成功后，POST /oa-api/orders/task-links 接收 shop_id、sku、from、to、task_id。验证经营范围、SKU 成交和原生任务读取授权后保存快照。(shop_id,sku,task_id) 重复提交复用该关联。来源 SKU 可以不同于新任务 SKU。
- SKU 当前价仅取 /v1/cost-management/sku-costs 当前可见的精确 SKU。改价从原生维护入口办理。历史订单单位成本独立从 ClickHouse 查询。
- 反馈和任务来源关联只写 OA 扩展库。未启用扩展库时查询仍可工作，关联和反馈返回 503。

迁移 152 负责创建扩展表。运行中的订单包没有 DDL。订单源写入接口只保存关联与观察快照，填写调用者当前可见的原生任务 ID。反馈关联任务时要求已有同一店铺与 SKU 的任务关联，并再次调用原生任务接口验权。填报日期为北京时间。查询日期首尾包含，SQL 转为下单时间半开区间。

性能参考来自正式订单开放视图的 ECS 只读对照。八个实际店铺同一天、每店各一次并发查询。按订单 ID 预筛选的商品 SQL P95 为 186.5ms，旧扫描方案为 1002.5ms，累计行量按单次从约 634.5 万降至 17.5–17.8 万。该证据仅覆盖数据源查询，正式 OA HTTP 端到端并发需要以正式候选版重新验收。

## 订单 SKU 与成本规则

商品表现按店铺、宝贝和订单开放层 `v_order_lines.sku_id` 分组，OA 返回的 `sku` 是原聚水潭商品编码。详情路径对该编码转义一次；成本规则使用解码后的原值查询。款号、平台 SKU ID、宝贝 ID 和商品名称不作为编码替代。原生成本维护清单来自已完成／归档任务或有同码完成历史的任务规格，关键字也会匹配名称等字段；OA 只采用唯一一条 `sku_code` 与订单编码完全一致的记录，并核对调用人是否可读关联任务。

成交核实成本是下单时点的订单指标。当前系统单位成本取自匹配行的 `cost_price`，ERP 最近观测成本是独立字段 `erp_cost`。无同码维护记录、有记录但未填维护价、暂时无法核对三种状态分别展示。当前范围内订单行的 `cost_amount` 为 NULL 时计入 `missing_cost_lines`，提供核价入口并预填原因。核价仅记录该店铺、编码、日期范围和原因；登记新价格仍需有依据的明确维护操作。
