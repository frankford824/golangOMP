# 经营排行接口对接清单

供订单开放层与 OA 接口维护人对接。现网消费端使用 `GET /oa-api/orders/rankings`。以下是待提供的能力，本轮未变更接口。

| 场景 | 现状 | 希望接口提供 | 验收示例 |
|---|---|---|---|
| 商品名称 | 商品榜行返回店铺和平台宝贝 ID 及商品销售额。前端能从相同店铺、宝贝、时间和业务筛选的 SKU 明细中补到展示名。 | 在现有店铺＋宝贝分组内返回可读名称，并明确多名称时的取名规则。保留原标识。 | 同 ID 跨店不能串名，多标题不能拆成多个名次，取名不改变原金额。 |
| 人员姓名 | 人员榜只返回名册 `person_id` 和归属商品销售额，未提供姓名。 | 在权限范围内用 `person_id` 关联 `v_reg_person.name`，保留原标识。对缺名和历史归档单独定义显示规则。 | 匹配姓名前后，行数、名次和金额一致；人员排行继续仅对超级管理员开放。 |
| 跨页升降序 | 现有接口先固定降序再每 100 行分页。前端只对完整结果或当前页排序。 | 提供受控的排序指标和方向，在数据库分页前排序；规定同分次序、空值位置和适用维度。 | 超过 100 组时，升序第一页含全量最低值；同分跨页无重复或漏行。旧请求默认降序。 |

归属人员可以重叠。同一商品行对应多人时，不能直接累加人员销售额作为公司总额。SKU、宝贝、人员与店铺各自的分组粒度应在接口说明中分别列出。
